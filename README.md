# Дети Марии — портал волонтёров

Портал для благотворительной организации «Дети Марии»: регистрация волонтёров, анкеты, мероприятия, обучение и работа команды фонда.

## Возможности

- Вход по четырёхзначному коду из письма или паролю, подтверждение почты и восстановление доступа.
- Личный профиль с городом и анкета с интересами, навыками и доступностью; сохранение черновиков и импорт прежних анкет из CSV с предпросмотром.
- Каталог возможностей с фильтрами, отклики, приглашения, списки участников и учёт часов.
- Курсы с уроками, вопросами и сохранением прогресса; проверка обязательной подготовки при отклике и подтверждении участия.
- Группы мероприятий, личные диалоги участников, объявления организаторов и автоматические напоминания.
- Рабочие задачи, обращения в фонд и внутренние рассылки.
- Аналитика, журнал действий и выгрузка данных для администратора.
- Архив мероприятий и курсов с восстановлением и сохранением истории участия.
- Кистик — помощник по разделам и правилам работы портала.

Роли: **волонтёр**, **координатор**, **руководитель** и **администратор**. Волонтёр получает собственные данные и связанные с ним события. Права сотрудников зависят от роли; сервер проверяет доступ к каждому закрытому действию. Самостоятельная регистрация создаёт волонтёра.

## Архитектура

Один монолит обслуживает интерфейс и API с общего домена. PostgreSQL хранит пользователей, сессии, записи участия и очереди фоновых задач. Обработчики уведомлений, кодов входа и напоминаний работают внутри процесса приложения.

Caddy принимает HTTPS и передаёт запросы приложению. База данных и Ollama доступны во внутренней сети контейнеров. Для фронтенда отдельный сервер не нужен. Текущая схема рассчитана на один экземпляр приложения: ограничения запросов и часть очередей исполнения находятся в памяти процесса.

### Кистик и Qwen

Кистик использует **Qwen3 0.6B** в квантизации **Q4_K_M**. Модель работает через Ollama на сервере проекта и подбирает подходящие карточки из справочника портала. Сервер проверяет выбранные факты и разрешённые для роли пользователя ссылки, затем формирует ответ и действие перехода.

В модель не передаются записи анкет и переписка из базы. Помощник не меняет данные пользователя. При недоступности модели или неподходящем ответе используется встроенный справочник. Модель не скачивается при обычном запуске приложения: её установка выполняется отдельным операторским скриптом.

В Compose для Ollama заданы лимиты **1 CPU / 1536 МиБ**, один одновременный запрос и контекст 2048 токена. Веса не входят в репозиторий. Qwen3 распространяется по Apache 2.0: [карточка модели](https://huggingface.co/Qwen/Qwen3-0.6B), [сборка Ollama](https://ollama.com/library/qwen3:0.6b).

## Быстрый запуск

Нужен Node.js **24**. Версия закреплена в `.nvmrc`.

```sh
npm ci
npm run demo
```

Откройте <http://localhost:3000>. Демонстрационная база сохраняется в `.local/demo/`; пароли локальных аккаунтов записываются в `.local/demo-access.txt` с закрытыми правами. Эти файлы не включаются в Git. Повторный запуск сохраняет данные. Остановка — `Ctrl+C`.

На macOS также можно запустить `Запустить прототип.command`; Node.js должен быть установлен заранее.

### Локальная PostgreSQL

```sh
node scripts/configure.mjs --mode local
docker compose up -d --build
```

Генератор создаёт `.env` со случайными секретами и не перезаписывает существующий файл. Для регистрации новых пользователей требуется почтовый транспорт. Первого администратора можно создать вручную:

```sh
PORTAL_COMPOSE_FILE=docker-compose.yml bash scripts/create-admin.sh
```

### Развёртывание на сервере

Нужны Linux, Docker Engine с Compose, домен с DNS-записью на сервер и доступ по SSH. Подробные шаги: [развёртывание и резервные копии](docs/PUBLIC-LAUNCH.md).

```sh
node scripts/configure.mjs --mode production --domain volunteers.example.org
# Заполните почту, ссылки на документы и остальные настройки в .env.
docker compose -f compose.production.yml up -d --build --wait
bash scripts/create-admin.sh
```

Миграции применяются перед запуском приложения. `.env`, базы, загрузки, SSH-ключи и резервные копии хранятся отдельно от исходников.

## Почта и настройки

Основные параметры описаны в `.env.example`. Для Unisender Go задайте `MAIL_TRANSPORT=unisender_go`, ключ API и адрес отправителя. Для SMTP используйте `MAIL_TRANSPORT=smtp` и параметры `SMTP_*`. Ключи передаются только серверу, браузер обращается к API портала.

Обычные коды — четыре случайные цифры, срок действия 10 минут; повторный запрос доступен через 30 секунд. Для почты без аккаунта форма входа предлагает зарегистрироваться. Тестовый вход с кодом `1234` включается только для явно перечисленных существующих адресов в `EMAIL_DEMO_ACCOUNTS`; по умолчанию список пуст. Регистрация всегда использует настоящее письмо.

До открытия регистрации заполните `PRIVACY_URL`, `RULES_URL` и `CONSENT_VERSION`, настройте отправителя и задайте `REGISTRATION_ENABLED=true`. Подробнее: [почтовый транспорт](docs/MAIL.md).

## Команды

| Команда                  | Назначение                                               |
| ------------------------ | -------------------------------------------------------- |
| `npm start`              | Запуск сервера                                           |
| `npm run dev`            | Сервер с перезапуском при изменении файлов               |
| `npm run demo`           | Локальная демонстрация с PGlite                          |
| `npm run db:migrate`     | Применение миграций                                      |
| `npm run admin:create`   | Создание администратора из окружения                     |
| `npm run password:reset` | Операторский сброс пароля                                |
| `npm run demo:cards`     | Добавление демонстрационных карточек с явным разрешением |
| `npm test`               | Локальные тесты                                          |

`npm run demo:cards` предназначен для подготовленного окружения и требует `DEMO_CARDS_APPLY=true`. [Состав и порядок добавления примеров](docs/DEMO-CARDS.md).
