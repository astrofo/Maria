# Внутренние сообщения

Раздел «Сообщения» (`#groups`) объединяет группы мероприятий и личные разговоры их участников. Он работает внутри монолита на PostgreSQL; отдельный чат-сервер не требуется. Открытый разговор получает новые сообщения опросом API, при скрытой вкладке опрос приостанавливается.

## Группы мероприятий

Группа создаётся автоматически вместе с мероприятием, в том числе для уже существующих встреч при миграции. Волонтёр получает доступ после подтверждения участия; для закрытой встречи требуется действующее приглашение. Координатор видит свои мероприятия, руководитель и администратор — группы мероприятий фонда.

Участники могут писать сообщения и открывать список участников. Организаторы группы могут публиковать объявления. Системные сообщения появляются при изменении даты, времени, места, статуса и подготовки, а также перед началом встречи. Отправленная внутренняя рассылка по мероприятию копируется в его группу один раз. Эти сообщения не рассылаются на почту.

Отмена участия и отзыв приглашения прекращают доступ к соответствующей группе. Закрытые и архивные встречи доступны прежним участникам только для чтения. В списке участников нет адресов почты, телефонов и ответов анкеты.

## Личные диалоги

Откройте список участников группы и выберите «Написать лично». Разговор связан с этой встречей и доступен только двум собеседникам, пока оба сохраняют доступ к ней. Наличие роли администратора само по себе не открывает чужую личную переписку через чат. Административная выгрузка данных и резервная копия включают переписку, поэтому должны храниться как закрытые данные проекта.

В разделе «Обращения в фонд» (`#messages`) сохраняется прежний список вопросов с главной страницы. Его читают руководитель и администратор. «Чат с фондом» остаётся доступен посетителям.

## API

Все маршруты требуют авторизации; для POST необходим CSRF.

| Метод | Маршрут                                | Назначение                                                                           |
| ----- | -------------------------------------- | ------------------------------------------------------------------------------------ |
| GET   | `/api/groups?page=1&page_size=20`      | Доступные группы и личные диалоги, превью и непрочитанные                            |
| GET   | `/api/groups/unread-count`             | Общее количество непрочитанных сообщений в доступных разговорах                      |
| GET   | `/api/groups/events/:eventId`          | Группа конкретной встречи, ответ `{ item }`                                          |
| GET   | `/api/groups/:id/messages`             | Последние 50 сообщений, `{ group, items, has_more }`                                 |
| GET   | `/api/groups/:id/messages?before_id=…` | Предыдущая страница истории                                                          |
| GET   | `/api/groups/:id/messages?after_id=…`  | Следующие сообщения после известного курсора                                         |
| POST  | `/api/groups/:id/messages`             | `{ body, client_id, kind: "message" }`; организатору доступен `kind: "announcement"` |
| POST  | `/api/groups/:id/read`                 | `{ message_id }`, прочтение до указанного сообщения                                  |
| GET   | `/api/groups/:id/members?q=…&page=1`   | Поиск участников доступной группы                                                    |
| POST  | `/api/groups/:id/direct`               | `{ user_id }`, создать или открыть личный разговор в контексте встречи               |

`before_id` и `after_id` нельзя передавать одновременно. История возвращается в порядке возрастания ID. Поле `has_more` означает наличие ещё одной страницы в запрошенном направлении. Собственная отправка не заменяет курсор прочитанной с сервера истории: между запросом и отправкой могли появиться сообщения собеседника.

`client_id` — UUID одной отправки. При повторе после сетевого сбоя используйте тот же UUID и текст: сервер вернёт ранее созданное сообщение. Другой текст с этим UUID отклоняется. Текст ограничен 4000 символами; действует ограничение частоты запросов и 120 сообщений от пользователя за час во всех группах. Системные объявления используют отдельные ключи повторной доставки.

Готовые методы находятся в `api.groups` файла `integration/api-client.js`. Фронтенд дополнительно проверяет `read_only` и `can_announce` для отображения действий; окончательное решение всегда принимает сервер по текущей роли, участию и приглашению.
