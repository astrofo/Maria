# Ollama и Qwen для Кистика

Кистик использует локальную **Qwen3 0.6B Q4_K_M** через Ollama. Модель выбирает факты из справочника приложения; текст ответа и допустимые переходы формируются сервером. Подробности контракта: [ASSISTANT.md](ASSISTANT.md).

[Карточка Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B) и [сборка Ollama](https://ollama.com/library/qwen3:0.6b) указывают лицензию Apache 2.0. Закреплённый файл весов занимает около 523 МБ. Веса скачиваются при подготовке окружения и не хранятся в репозитории.

## Конфигурация

- Runtime закреплён в `compose.production.yml` по версии и digest.
- Модель — `qwen3:0.6b`; исходный manifest находится в `deploy/assistant-model-manifest.json`.
- Контрольные суммы весов, manifest, шаблона, лицензии и параметров — в `deploy/assistant-model.sha256`.
- Контейнер ограничен 1536 МиБ, 1 CPU и 128 процессами. Контекст — 2048 токена, ответ — до 224 токенов, thinking выключен.
- Одновременно выполняется один запрос модели, в очереди ожидает не более двух. При ошибке или превышении времени приложение возвращает ответ справочника.
- Неиспользуемая модель выгружается через две минуты.

Планируйте ресурсы всего сервера с учётом приложения и PostgreSQL. Размер файла весов не равен потреблению оперативной памяти. Изменение модели требует пересмотра лимитов и проверки качества ответов.

## Подготовка

На Linux-сервере с Docker выполните от root из корня проекта. По умолчанию каталог установки — `/opt/deti-marii`; другой задаётся через `PORTAL_PROJECT_ROOT`:

```sh
bash scripts/prepare-assistant.sh
```

Скрипт скачивает закреплённый образ и артефакты модели, проверяет контрольные суммы и заполняет отдельный Docker volume. Повторный запуск использует проверенные артефакты. Требуются доступ к реестрам и свободное место для образа и весов.

После подготовки добавьте в `.env`:

```dotenv
COMPOSE_PROFILES=assistant
ASSISTANT_ENABLED=true
ASSISTANT_URL=http://ollama:11434
ASSISTANT_MODEL=qwen3:0.6b
ASSISTANT_TIMEOUT_MS=35000
ASSISTANT_QUEUE_LIMIT=2
ASSISTANT_NUM_CTX=2048
ASSISTANT_NUM_PREDICT=224
```

Примените конфигурацию:

```sh
docker compose -f compose.production.yml up -d --wait
```

## Сетевая изоляция

Ollama находится в сети `assistant_internal` с `internal: true`, общей только с приложением. Порт 11434 не публикуется на хосте. Runtime не получает тома БД, пользовательские загрузки, почтовые ключи или Docker socket. Том с моделью подключён только для чтения.

Клиент сайта обращается к `/api/assistant/chat` монолита. Он не получает адрес runtime и не вызывает Ollama напрямую. Записи из пользовательских таблиц в модель не передаются; приложение не сохраняет тексты диалогов Кистика в базе и журнале.

## Отключение модели

Пустой `ASSISTANT_URL` оставляет Кистика в режиме справочника. Для полного отключения API помощника установите `ASSISTANT_ENABLED=false`. После изменения окружения пересоздайте контейнер приложения. Если runtime больше не требуется, остановите сервис `ollama`; сохранённый volume можно использовать при следующем включении.

Проверка здоровья контейнера подтверждает доступность runtime и контрольную сумму manifest. Все файлы модели проверяет установочный скрипт. Оценку качества ответов и времени генерации проводите отдельно на характерных вопросах пользователей.
