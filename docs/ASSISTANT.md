# Кистик

Кистик объясняет работу портала и помогает открыть раздел. Он не читает анкеты,
переписку, отчёты или записи об участии и не изменяет данные пользователя.
Даты и наличие мероприятий предлагается смотреть в живом каталоге.

## Ответы и навигация

`GET /api/assistant/config` возвращает `enabled`, `model_configured`, `mode`,
`examples`, `max_message_length: 1000`, `max_history: 6` и `allowed_hrefs`.
`model_configured` означает наличие допустимой локальной конфигурации, а не
проверку запущенной модели. Фактический режим указан в каждом ответе чата.

`POST /api/assistant/chat` принимает:

```json
{
  "message": "Открой мою анкету",
  "history": [{ "role": "user", "content": "Как начать?" }],
  "current_route": "#kistik"
}
```

Сообщение и каждая запись истории — от 1 до 1000 символов после обрезки пробелов;
история — максимум 6 сообщений с ролями `user` и `assistant`. `current_route`
необязателен (до 120 символов); неизвестные или недоступные маршруты игнорируются.
История не является источником фактов. Для короткого уточнения может использоваться
небольшой фрагмент предыдущего вопроса пользователя; ответы из истории игнорируются.

Ответ содержит `answer` (обычный текст), `actions: [{id,label,href}]`,
`sources: [{title,href}]`, `mode: "model" | "guide"`. При однозначной прямой
просьбе открыть доступный раздел добавляется `navigateTo`. Решение о переходе
принимает сервер; FAQ и неоднозначные просьбы автоматически никуда не переводят.
Клиент должен выводить текст с экранированием и принимать только разрешённые
локальные hash-ссылки. `navigateTo` отсутствует в ошибках и ответах об ограничении.

Роль берётся из проверенной серверной сессии. Гость видит публичные возможности,
описание фонда и страницы входа. Личные страницы требуют входа; аналитика,
рассылки и общий список диалогов доступны руководителю/администратору, управление
правами и аудит — администратору. Ссылки на чужие анкеты не создаются. Статус
регистрации определяется `registrationEnabled && mailer.available`; наличие
почтовой конфигурации не гарантирует доставку письма. Вход по паролю остаётся
запасным способом входа.

POST требует cookie сессии и `X-CSRF-Token` из `/api/auth/csrf`, включая гостей.
Лимиты на один процесс: 20 запросов за 5 минут на сессию, 60 за 5 минут на IP.
HTTP 429 содержит `code: "ASSISTANT_RATE_LIMIT"`, `retry_after`, `Retry-After`
и полезный ответ в режиме `guide`. При выключении — HTTP 503 с
`code: "ASSISTANT_DISABLED"` и ссылками на основные разделы.

## Локальная модель

Настройки приложения:

| Переменная              | Значение / ограничение                                             |
| ----------------------- | ------------------------------------------------------------------ |
| `ASSISTANT_ENABLED`     | `false` выключает API чата; по умолчанию включён                   |
| `ASSISTANT_URL`         | `http://ollama:11434`; пустое значение оставляет только справочник |
| `ASSISTANT_MODEL`       | `qwen3:0.6b` по умолчанию; локальная модель, не cloud              |
| `ASSISTANT_TIMEOUT_MS`  | 35000 по умолчанию, 1000–35000, включая очередь                    |
| `ASSISTANT_QUEUE_LIMIT` | 2 по умолчанию, 0–2 ожидающих                                      |
| `ASSISTANT_NUM_CTX`     | 2048 по умолчанию, 1024–2048                                       |
| `ASSISTANT_NUM_PREDICT` | 224 по умолчанию, 64–256                                           |

Допустим только HTTP endpoint Ollama на `ollama`, `localhost`, `127.0.0.1` или
`[::1]`, порт 11434 (или стандартный HTTP при отсутствии порта), без пути,
учётных данных и query. Неизвестный endpoint или cloud-имя отключает модель и
оставляет справочник. Порт Ollama не следует публиковать в интернет. Модель
загружается отдельно средствами развёртывания; приложение ничего не скачивает.

Одновременно выполняется один запрос модели. Полная очередь, таймаут, ошибка,
некорректный ответ или отсутствие подходящего факта возвращают `guide`.
После ошибки соединения/инференса действует пауза 30 секунд. Уход клиента
отменяет его запрос; HTTP-ответ модели ограничен 64 КиБ. Используются
`stream:false`, `think:false`, `keep_alive:"2m"`, `num_thread:1`,
`num_batch:128`, `num_gpu:0`, `temperature:0`.

Модель выбирает максимум два `fact_ids` из небольшого серверного справочника.
Поиск сначала отбирает до пяти подробных карточек; при отсутствии совпадений
модель получает компактный каталог всех разрешённых тем (до 20), чтобы распознать
нестандартную формулировку либо отказаться от ответа вне справочника.
Сервер проверяет результат по перечню кандидатов и собирает ответ из проверенных
формулировок. Поэтому `model` означает реальный выбор фактов локальной моделью,
а не свободную генерацию текста. Произвольный текст, HTML, ссылки и команды
модели никогда не попадают в ответ. При неизвестном вопросе Кистик честно
объясняет границы справочника. Тексты запросов, история и ответы не сохраняются
в БД или журналах приложения. В модель не передаются строки пользовательских
таблиц; после ожидания права сессии дополнительно проверяются.

Карточки и маршруты находятся в `src/assistant-knowledge.js`; их нужно обновлять
при изменениях возможностей сайта. Контекст модели не является механизмом
авторизации: правила доступа и адреса определяет серверный код.

Формат транспорта основан на официальных документах
[Ollama Chat API](https://docs.ollama.com/api/chat) и
[Structured outputs](https://docs.ollama.com/capabilities/structured-outputs).
