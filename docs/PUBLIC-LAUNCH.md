# Развёртывание и обслуживание

Приложение, PostgreSQL и Caddy работают на одном Linux-сервере. Ollama подключается отдельным профилем Compose. База и runtime модели не публикуют порты наружу.

## Подготовка

Нужны Docker Engine с Compose, Node.js 24, Python 3, `rsync`, `tar`, `flock` и доступ по SSH. Node.js используется генератором конфигурации, Python — скриптами установки. Для HTTPS откройте TCP 80/443; SSH ограничьте своим способом доступа. Создайте DNS-запись `A` домена на IPv4 сервера. Для перенаправления с `www` добавьте также `A` или `CNAME` для этого имени. Запись `AAAA` добавляйте только при работающем IPv6.

Скопируйте исходники в `/opt/deti-marii`, перейдите в этот каталог и создайте конфигурацию:

```sh
node scripts/configure.mjs --mode production --domain volunteers.example.org
```

Генератор создаёт случайные пароли БД и секрет сессий, сохраняет `.env` с закрытыми правами и не заменяет существующие настройки. Заполните почтовый транспорт, утверждённые ссылки `PRIVACY_URL` / `RULES_URL` и `CONSENT_VERSION`. До готовности почты оставьте `REGISTRATION_ENABLED=false`.

```sh
docker compose -f compose.production.yml up -d --build --wait
bash scripts/create-admin.sh
```

Первый администратор создаётся интерактивно. Пароль не передавайте в аргументах команд и не сохраняйте в Git. Caddy получает сертификат автоматически, когда DNS и порты доступны.

## Подключение домена к существующей установке

Проверьте DNS и запустите на сервере:

```sh
bash scripts/connect-domain.sh volunteers.example.org /opt/deti-marii
```

Скрипт сохраняет предыдущие настройки, делает резервную копию и подключает конфигурацию apex-домена и `www`. Смена домена не требует повторного создания базы. Параметр `FRONTEND_ORIGINS` нужен только для разрешённых отдельных адресов фронтенда; перечисляйте точные origins без масок.

Если домена ещё нет, `compose.server.yml` позволяет подготовить БД и приложение на loopback-интерфейсе сервера. Это подготовительный режим: production-cookie требуют HTTPS, поэтому он не заменяет публичное размещение.

## Обновление по SSH

С компьютера с проверенным SSH-доступом:

```sh
PORTAL_DEPLOY_HOST=deploy@server.example.org \
PORTAL_DEPLOY_ROOT=/opt/deti-marii \
bash scripts/deploy.sh
```

Пользователь SSH должен иметь доступ к каталогу и Docker. При первой установке также задайте `PORTAL_DEPLOY_DOMAIN=volunteers.example.org`. Для отдельного ключа используйте `PORTAL_SSH_IDENTITY`, для порта — `PORTAL_SSH_PORT`.

Скрипт передаёт только исходники, сохраняет резервную копию БД и загрузок, строит образ и ожидает готовности контейнеров. `.env` и данные остаются на сервере. Предыдущие исходники и файл с тегом образа сохраняются в `.releases/`; сам образ остаётся в Docker. Миграции не откатываются автоматически. При неудачном обновлении сначала определите причину и совместимость схемы, затем используйте сохранённые материалы восстановления.

## Резервные копии

Ручная копия:

```sh
bash scripts/backup.sh
```

Создаются архив PostgreSQL в формате `pg_dump` и архив загрузок. Временные сессии и запросы подтверждения/восстановления не переносятся. Файлы сохраняются в `.backups/` с закрытыми правами. Политика хранения рассчитана на 30 дней: сохраняются дневные и недельные копии, как минимум две последние и последняя копия перед обновлением.

Для ежедневного запуска на сервере с systemd:

```sh
sudo bash scripts/install-backup-timer.sh
```

`deploy.sh` устанавливает этот таймер при запуске от root. Проверить восстановление можно в отдельной временной базе:

```sh
bash scripts/check-backup.sh .backups/portal-example.dump
```

При успешной проверке временная база удаляется. При ошибке она сохраняется для разбора. Рабочая база не изменяется.

### Внешнее хранилище

Для копирования за пределы VPS создайте закрытый `.backup-offsite.env`:

```dotenv
PORTAL_OFFSITE_HOST=backup@storage.example.org
PORTAL_OFFSITE_DIR=/srv/backups/volunteer-portal
PORTAL_OFFSITE_PORT=22
PORTAL_OFFSITE_IDENTITY=/root/.ssh/portal_backup
```

Нужны заранее настроенные SSH-ключ и проверенный ключ хоста. Файл использует только перечисленные параметры в формате `KEY=value`; shell-команды не выполняются. Архивы передаются по SSH/SFTP, после передачи сравнивается SHA-256. При ошибке передачи локальные копии сохраняются. Защита и срок хранения внешних копий настраиваются на стороне хранилища.

## Эксплуатация

- `GET /api/health` проверяет доступность приложения и БД.
- Доступность контейнеров: `docker compose -f compose.production.yml ps`.
- Письма и их доставку проверяйте отдельно в кабинете почтового провайдера.
- Перед изменениями конфигурации сохраняйте её закрытую копию отдельно от исходников.
- Для нового развёртывания используйте собственные секреты; не копируйте рабочую базу в среду разработки.
