# Почта и коды подтверждения

Приложение поддерживает два транспорта: Unisender Go по HTTPS API и SMTP через Nodemailer. Транспорт выбирается явно; автоматического повторения через другого провайдера нет.

## Unisender Go

Сохраните настройки в закрытом `.env` на сервере:

```dotenv
EMAIL_CODE_MODE=random
MAIL_TRANSPORT=unisender_go
UNISENDER_GO_API_KEY=
UNISENDER_GO_FROM_EMAIL=noreply@volunteers.example.org
UNISENDER_GO_FROM_NAME=Дети Марии
UNISENDER_GO_BASE_URL=https://goapi.unisender.ru/ru/transactional/api/v1
```

Заполните API-ключ и подтвердите домен отправителя в кабинете сервиса. Допустимы официальные API-узлы `goapi.unisender.ru`, `go1.unisender.ru` и `go2.unisender.ru` с указанным путём. Запросы идут через HTTPS на порт 443; исходящие SMTP-порты этому транспорту не нужны.

Принятие задания API не гарантирует доставку во входящие. Статус доставки проверяется в кабинете провайдера. Ключ API не попадает в интерфейс, ответы приложения или журналы ошибок.

## SMTP

```dotenv
EMAIL_CODE_MODE=random
MAIL_TRANSPORT=smtp
SMTP_HOST=smtp.example.org
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=
SMTP_PASSWORD=
SMTP_FROM=noreply@volunteers.example.org
```

Для порта 587 используется обязательный STARTTLS. Для порта 465 задайте `SMTP_SECURE=true`. Нужны доступный с сервера SMTP-узел и учётные данные отправителя. Если провайдер поддерживает пароли приложений, используйте отдельный пароль для портала.

## Регистрация и вход

- Регистрация создаёт аккаунт волонтёра после подтверждения почты. Код состоит из четырёх случайных цифр; значение `1234` зарезервировано и не генерируется.
- Код действует 10 минут, повторный запрос доступен через 30 секунд. Применяются ограничения по адресу и IP. При входе повторный запрос сохраняет число неверных попыток; при регистрации новый код начинает новый счётчик попыток.
- Вход по коду работает для существующего незакрытого аккаунта. Письмо отправляет очередь внутри монолита.
- Отсутствующий аккаунт получает `404 account_not_found` и предложение зарегистрироваться. Закрытый — `403 account_unavailable`. Отправки письма в этих случаях нет.
- Вход по паролю остаётся доступен. Восстановление пароля использует короткоживущую одноразовую ссылку.

### Тестовые аккаунты

`EMAIL_DEMO_ACCOUNTS` содержит точные адреса существующих тестовых аккаунтов через запятую. По умолчанию переменная пуста. Маски и целые домены не поддерживаются.

```dotenv
EMAIL_DEMO_ACCOUNTS=tester@example.test
```

Только указанный аккаунт может войти по коду `1234` после запроса кода в том же браузере. Письмо не отправляется, владение почтой не считается подтверждённым. Восстановление пароля письмом и самостоятельная регистрация этих адресов отключены. Для отключения тестового входа очистите список. Используйте `EMAIL_CODE_MODE=random`, в том числе при наличии тестового списка.

## Применение настроек

После изменения `.env` пересоздайте приложение:

```sh
docker compose -f compose.production.yml up -d --no-deps --force-recreate --wait app
```

Для публичной регистрации также нужны `REGISTRATION_ENABLED=true`, `PRIVACY_URL`, `RULES_URL` и версия согласий `CONSENT_VERSION`.

`GET /api/config` сообщает доступность настроенного транспорта через `email_verification_available`, `email_login_available` и `password_recovery_available`. Эти флаги не являются проверкой доставки. `email_demo_login_available` указывает наличие тестового списка. Код никогда не возвращается в обычном ответе API; `demo_code` допустим только для успешного запроса тестового входа. Авторизованный профиль содержит `email_demo_account`.
